1. Vision

Beatality takes a set of audio samples that share one tempo but differ in length and turns them into a loop that keeps changing. The loop is split into equal time slots. Each slot is randomly given one of the loaded samples, and that sample plays the part of itself that matches the current musical position. You get a stuttering, shuffled mix of the source material that always stays on the beat and can be regenerated by hand or automatically every few loops.

The goal is a fast generator of beat variations for producers, both inside a DAW (VST) and as a playable toy on a website (web widget).

2. Glossary

TermMeaning
TrackOne loaded audio sample. Tracks form an ordered list with indices 0..N-1.
BeatOne beat at the given BPM: 60 / BPM seconds. Beats are the base unit for every musical length in Beatality.
LoopThe full repeating cycle that Beatality plays, Loop Size beats long.
SliceA section of time Slice Size beats long. Tracks are divided into slices mathematically; the audio is never cut up.
SlotOne slice-length position inside the loop. The loop holds a whole number of slots.
SequenceAn ordered list of track indices, one per slot. For example [2, 0, 0, 3, 1, 2, 0, 1].
Saved Track CountThe number of tracks loaded when the sequence was generated. It is stored together with the sequence.
Start PositionA per-track offset from 0.0 to 1.0 (a fraction of the track's length) that marks where the track's slicing begins. Audio before this point is discarded.
Loop CounterThe number of full loops completed since the sequence was last generated.
Units. Slice Size and Loop Size are both measured in beats. Bars aren't used anywhere, so no time signature is needed. In 4/4, 4 beats = 1 bar.

3. Inputs & parameters

3.1 Global parameters

ParameterRange / valuesDescription
Audio samples 0…N files The samples to use, all at the same BPM. Their lengths can differ. See section 4.
BPM Positive number The tempo of the source samples, and also the tempo Beatality plays at. In the VST this BPM is set inside the plugin and does not follow the host tempo.
Loop Size 1, 2, 3 … 32 (beats) How long the generated loop is.
Slice Size 1/64, 1/32, 1/16, 1/8, 1/4, 1/2, 1, 2, 4, 8, 16 (beats) How long each slot is. Examples: 1 = 1 beat, 4 = 1 bar in 4/4, 1/64 = 1/64 of a beat. Slice Size can never exceed Loop Size; larger values are unavailable. If Loop Size drops below the current Slice Size, Slice Size is lowered automatically (section 10).
Randomize Every (web only) -1, 1, 2, 3 … 8 (loops) How many completed loops pass before the sequence is regenerated automatically. -1 means it is only regenerated by hand. The VST doesn't have this setting.
Playback Mode (VST only) Trigger / Gate How MIDI notes control playback. See section 5.1.

3.2 Per-track parameters

ParameterRangeDescription
Start Position 0.0 … 1.0 Where in the track slicing starts, as a fraction of the track's total length. Audio before this point is discarded and never plays.

Every parameter can be changed while the sequencer is playing. Section 10 describes what happens in each case.

4. Track list management

The track list works the same way in the VST and the web widget.

ActionBehavior
Add sample(s)New samples are added to the end of the list. Several can be added at once. Existing indices don't change.
Delete sample at index iThe sample is removed, and every sample after it moves up by one index.
Move sample from index i to index jThe sample ends up at index j. The samples between i and j shift by one index to close the gap. The number of samples doesn't change.
Edit Start PositionEach track has its own Start Position control.

Samples can be added, deleted or moved during playback. The sequence is not regenerated when this happens. After an add or delete, its stored indices are remapped onto the current list (section 8.3). A move does not change the sequence, and the sequence is not told about the move: each slot keeps its stored index, so it plays whichever sample is now at that index.

5. Transport

The two versions start and stop playback differently.

5.1 VST: driven by MIDI notes

The VST has no Play/Stop button. Playback is controlled by MIDI notes on the plugin's track in the host (for example Ableton), and the Playback Mode setting decides how the notes are interpreted.

ModeNote OnNote OffPlayback stops when
Trigger Playback starts from the beginning of the loop (t = 0). Each new note restarts it from t = 0. Ignored. The host transport stops.
Gate Playback starts from the beginning of the loop (t = 0). Each new note restarts it from t = 0. Playback stops once no notes are held. The note is released, or the host transport stops.

A Note On is the same event as pressing Play in the web widget: playback starts from the beginning of the loop, and a sequence is generated only if none exists yet.

  • Note pitch and velocity have no effect.
  • A new note while Beatality is already playing restarts the loop from t = 0 in both modes. It does not generate a new sequence.
  • If no sequence exists yet, for example in a fresh plugin instance or after a project is reopened, the first note generates one and plays it. After that, only the Randomize button generates a new sequence, plus the structural rules in section 10 (a Slice Size change, or Loop Size dropping below Slice Size).
  • There is no Loop Counter and no Randomize Every in the VST.
ControlBehavior
Randomize buttonGenerates a new sequence immediately, whether or not it is playing.

5.2 Web widget: Play/Stop button

ControlBehavior
PlayPlayback starts from the beginning of the loop (t = 0) and the Loop Counter resets to 0. On the first Play, if Randomize hasn't been pressed yet, a new sequence is generated and played. Later presses play the existing sequence.
StopPlayback stops and the playhead returns to t = 0. The sequence is not regenerated, so the next Play repeats the same sequence from the beginning.
RandomizeGenerates a new sequence immediately. It works both while playing and while stopped.

6. Core model: time, slots, slices

6.1 Durations

beat = 60 / BPM (seconds) sliceLen = SliceSize × beat loopLen = LoopSize × beat

6.2 Slots in the loop

slotCount = floor(LoopSize / SliceSize) remainder = loopLen − slotCount × sliceLen

If the loop length isn't an exact multiple of the slice length, the leftover time at the end of the loop (remainder) after the last full slot is silent. The loop length always stays exactly LoopSize beats.

6.3 Slices in a track

Each track is divided into slices starting at its Start Position. The usable length is rounded to the nearest whole number of slices. This absorbs small timing inaccuracies in sample files:

  • A sample slightly longer than a whole number of slices has the extra audio discarded.
  • A sample slightly shorter than a whole number of slices has the missing time filled with silence.
trackLen_i = duration of track i (seconds) startOffset_i = StartPosition_i × trackLen_i (audio before this is discarded) usableLen_i = trackLen_i − startOffset_i sliceCount_i = max(1, round(usableLen_i / sliceLen))

Slice j of track i covers [startOffset_i + j × sliceLen, startOffset_i + (j+1) × sliceLen) in the track's own timeline. If that range runs past the end of the audio, the part beyond the end is silent.

7. Sequence generation

  • The sequence has slotCount elements.
  • Each element is a track index chosen uniformly at random from 0..N-1, with replacement. There are no constraints: the same track can appear in several slots, including next to itself, and some tracks may not appear at all.
  • The randomness is unpredictable: every instance starts from a fresh random seed, and the seed is never shown or stored.
  • When a sequence is generated, the current number of tracks is stored as the Saved Track Count (savedCount).
  • A sequence is generated when:
    • playback starts (Note On / Play) and no sequence exists yet,
    • Randomize is pressed,
    • the Loop Counter reaches Randomize Every (web only, section 9),
    • Slice Size changes, either by the user or automatically when Loop Size drops below it (section 10).
  • When Loop Size grows, only the new slots are generated, using the existing savedCount (section 10).

8. Playback rules

While playing, the transport keeps a loop-relative time t in [0, loopLen), which wraps to 0 at the end of each loop.

8.1 Which track is playing

slot = floor(t / sliceLen) if slot ≥ slotCount → silence (remainder zone) else → i = effectiveIndex(sequence[slot]) (see 8.3)

8.2 Which part of the track is playing

The selected track plays the part of itself that corresponds to the current play time, not its own beginning. So a track always lines up with the beat grid, as if every track were playing in sync and Beatality just switched between them.

localOffset = t − slot × sliceLen (position inside the slot) trackSlice = slot mod sliceCount_i (time wraps if track is shorter) readPosition = startOffset_i + trackSlice × sliceLen + localOffset

Time wrapping. If a track has fewer slices than the loop has slots, its slice index wraps with slot mod sliceCount_i, so the short sample starts again from its Start Position.

8.3 Index remapping when the track count changes

The sequence stores indices in the range of the savedCount tracks that existed when it was generated. If tracks are added or deleted during playback, so that the current count currentCount ≠ savedCount, each stored index is scaled onto the current list:

if currentCount == savedCount → effectiveIndex = storedIndex if currentCount == 0 → silence else → effectiveIndex = floor(storedIndex / savedCount × currentCount)

The result always falls in 0..currentCount-1. The stored sequence itself doesn't change. The mapping is applied at playback time, and the next regeneration sets savedCount to the current count.

8.4 Source switches

Any moment the sounding audio changes source, the outgoing audio fades from full level to silence while the incoming audio fades from silence to full level. The two overlap, so there is no gap and no hard cut. This covers:

  • the playhead crossing a slot boundary,
  • Randomize (manual or automatic) replacing the sequence while audio is playing,
  • a Slice Size change, including one caused by lowering Loop Size,
  • a Start Position edit on the track that is currently sounding,
  • loading a preset while audio is playing.

The fade is about 10 ms (0.01 s). That is short enough that it isn't heard as a fade, and long enough to remove the click from cutting a waveform mid-sample. If the current slot is shorter than 10 ms, the fade is shortened to fit inside the slot.

A fade-in of the new audio alone doesn't remove the click, because the old audio is still cut instantly. Waiting for the next beat avoids some cuts, but it delays Randomize by up to a whole beat and still cuts mid-sample whenever the slice is longer than one beat. The crossfade keeps Randomize immediate.

9. Randomization cycle

A manual Randomize works the same way on both platforms. The automatic cycle (Loop Counter and Randomize Every) exists only in the web widget.

  • The Loop Counter goes up by 1 each time the playhead wraps from the end of the loop back to t = 0.
  • If Randomize Every ≠ -1 and LoopCounter ≥ Randomize Every, a new sequence is generated at that loop boundary and the counter resets to 0.
  • A manual Randomize takes effect immediately. The new sequence replaces the old one, the playhead keeps its current time t, the current slot is read from the new sequence, and (in the web widget) the Loop Counter resets to 0. If audio is playing, the switch is crossfaded (section 8.4).
  • Changing Randomize Every during playback is checked at the next loop boundary against the current counter. If the new value is ≤ the counter, the sequence regenerates at that boundary.

10. Live parameter changes

All parameters can be changed during playback, and every change takes effect immediately. The playhead time t is kept unless stated otherwise.

ChangeBehavior
Slice Size Slot count and track slice counts are recalculated, and the whole sequence is regenerated right away. The playhead keeps its time t and continues in the new slot grid.
Loop Size: decreased The sequence is cropped to the new slot count, and the existing slots that still fit are kept. If the playhead is past the new loop end, it wraps (t mod newLoopLen).
Loop Size: decreased below Slice Size Slice Size is lowered automatically to the largest valid value that is ≤ the new Loop Size. This counts as a Slice Size change, so the whole sequence is regenerated instead of cropped. Example: Loop 16 / Slice 16 → Loop 12 gives Slice 8 (1 slot plus 4 silent beats) and a new random sequence.
Loop Size: increased The existing sequence is kept as is, and newly generated random indices are appended for the new slots. They are drawn from 0..savedCount-1 so the whole sequence uses the same index range.
Randomize Every (web only) Checked at the next loop boundary (section 9).
Playback Mode (VST only) Applies to the next MIDI event. Switching from Trigger to Gate while no notes are held stops playback.
Start Position (per track) That track's offset and slice count are recalculated. The sequence is unchanged.
BPM Beat, slice and loop durations are recalculated. The audio is not time-stretched. To keep the playhead at the same musical position, t is scaled by oldBPM / newBPM. The sequence is unchanged.
Track added / deleted The sequence is unchanged, and indices are remapped as described in section 8.3.

11. Presets

A preset is a snapshot of the input settings. It does not contain the sequence, and it does not contain the loaded audio.

11.1 What a preset stores

StoredNot stored
  • BPM
  • Loop Size
  • Slice Size
  • Randomize Every
  • Playback Mode (Trigger / Gate)
  • Start Position of each track, in list order
  • Audio files: no bytes, no file paths, no file names
  • The sequence and savedCount
  • Playhead position and the Loop Counter

Randomize Every is stored so a preset made for the web keeps that setting. The VST saves and loads the value but does not use it. Playback Mode is stored so a preset made for the VST keeps that setting. The web widget loads the value but does not use it.

Start Positions and files. Because the audio itself is not in the preset, Start Positions are stored as a list and applied to whatever tracks are already loaded, matched by index. Position 0 goes to track 0, and so on. Positions past the current track count are ignored. Tracks past the end of the list keep the Start Position they already have. Loading a preset never adds, removes, or reorders samples.

11.2 Where presets come from

PlatformSaveLoad
Web widget No. The widget does not save presets. The user picks a preset hosted on the server and loads it.
VST The user saves the current settings as a preset file. The user loads a preset file they saved earlier.

The DAW project stores exactly the same settings as a preset, and nothing more (section 14.1). Neither presets nor projects contain samples or the sequence.

11.3 Loading

  • The stored settings are applied immediately, including during playback.
  • If the stored Slice Size is larger than the stored Loop Size, Slice Size is clamped to the largest valid value that fits, the same way as a live Loop Size change.
  • The current sequence is discarded.
  • If audio is playing, a new sequence is generated immediately and the switch is crossfaded (section 8.4).
  • If audio is stopped, the sequence stays empty. The next Play or Note On generates one, the same as a fresh start.

13. Edge cases

CaseExpected behavior
No tracks loadedPlayback runs silently. Randomize does nothing. If a sample is added while playing and there is no sequence yet, a sequence is generated at that moment.
All tracks deleted during playSilence (currentCount = 0). The stored sequence is kept and plays again, remapped, once tracks are added back.
One track loadedEvery slot uses the same track. The result is that track with its slices rearranged by time wrapping.
Track shorter than half a slicesliceCount is clamped to 1. The audio plays from the start of the slot, and the rest of the slot is silent.
Start Position = 1.0The usable length is 0, so the track is silent wherever it appears. The UI may cap the value just below 1.0.
Slice Size > Loop SizeNever allowed. If Loop Size is lowered below Slice Size, Slice Size is clamped down and the sequence is regenerated (section 10).
Samples with different sample ratesAll samples play at the correct pitch and speed, matching the output sample rate.
Unsupported file typeThe file is rejected with a message and the track list doesn't change. Both products accept only WAV and MP3. An Ableton Live Clip (.alc) is not audio: it stores clip settings and points at a sample file, so it is rejected like any other unsupported file. The WAV or MP3 it points at can be added on its own.
VST project reopenedAll settings come back, the track list is empty, and there is no sequence. Stored Start Positions have no tracks to apply to, so they are dropped, the same as when a preset is loaded with no tracks.
Very small slices (1/64 beat at high BPM)Slots can be just a few milliseconds long. Declicking must still work, and the sound may turn into a buzzy granular texture. That is expected.
VST: plugin BPM ≠ host tempoBeatality plays at its own BPM, so it may drift against the host's grid. Keeping them matched is up to the user.

14. Platforms

14.1 VST plugin

  • An instrument plugin on a MIDI track that outputs stereo audio into the DAW (target host: Ableton Live). The first release is in the VST3 format.
  • A commercial, closed-source product.
  • MIDI notes start and stop playback according to the Playback Mode, Trigger or Gate (section 5.1). There is no Play/Stop button.
  • The sequence is regenerated only by the Randomize button, or by a Slice Size change. There is no Loop Counter or Randomize Every.
  • Tempo comes from the plugin's own BPM parameter. There is no host tempo sync or time-stretching for now.
  • The user can save the current settings as a preset and load a preset back (section 11). A preset does not include the samples or the sequence.
  • The DAW project stores the plugin's settings only, the same contents as a preset. Samples and the sequence are not stored, so after a project is reopened the user adds the samples again and the first note generates a new sequence.
  • Plugin parameters are not exposed to the DAW for automation.
  • Accepts WAV and MP3 files only.

14.2 Web widget

  • A self-contained player that can be embedded in the author's website.
  • Same core behavior as the plugin, with a Play/Stop button instead of MIDI (section 5.2).
  • Includes the automatic randomization cycle (Randomize Every and the Loop Counter), which the VST does not have.
  • Track list management works the same as in the plugin: add samples, delete the sample at an index, move a sample, edit Start Position.
  • Accepts WAV and MP3 files only.
  • The user can load a preset from the server (section 11). The widget does not save presets.
  • Has to work within browser rules, for example audio can only start after the user interacts with the page.

14.3 Shared behavior

Both versions follow this document as the single behavior spec. With the same samples, parameters and sequence, they should produce the same output. The intended differences are:

AspectVSTWeb widget
Starting / stoppingMIDI notes (Trigger / Gate)Play / Stop button
Automatic randomizationNoneRandomize Every with a Loop Counter
PresetsSave and load a preset fileLoad a preset from the server

15. Design direction

The interface will be styled after the classic Winamp player: a compact, skin-like window with a retro media-player feel. The visual design is out of scope for this document and will be specified separately.

The interface has to give access to these elements, whatever the final layout:

  • Transport: Randomize on both platforms, plus Play/Stop in the web widget only.
  • Global parameters: BPM, Loop Size and Slice Size, plus Randomize Every (web) or Playback Mode Trigger/Gate (VST).
  • A track list, similar to a playlist, with add and delete actions and a Start Position for each track.
  • Some indication of the current sequence and the playhead position. The web widget also shows how many loops remain before the next auto-randomize.
  • Presets: Save and Load in the VST, Load (from the server) in the web widget.

16. Future expansion

FeatureIdea
Variations Instead of full regeneration, mutate the current sequence: change only N slots, swap slots, shift the sequence, mirror it, and so on. This keeps the "feel" of a good sequence while still changing it.
FX Effects applied per slot or globally, such as reverse, stutter/retrigger, pitch, filter and gate, possibly also chosen at random.
Host sync / stretching Following the host tempo with time-stretching. This was deliberately left out for now.
Possible extras Per-track probability weights, locking individual slots so randomization skips them, triggering Randomize from MIDI, export of the current loop to audio or MIDI, and a sequence history with undo.
